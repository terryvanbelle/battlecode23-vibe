# Prepared native blind-readiness correctness probe

Prepared for official VM verification; no VM execution has occurred. A local **source-built prototype** with SHA-256 `bdc00ae46ff683a6de688c9ea7bfc46f2981077f59af9b07a81e5761bffec34f` compiled under JDK 8 and passed 13 cases / 205 assertions with empty stderr; this is not the official pinned artifact. Results and provenance are in `prototype-results.jsonl` and `prototype-provenance.json`.

Upload the Java file and launch script to scratch on **battlecode-dev**, then run `bash run.sh`. The script requires the existing checksum-pinned official 3.0.15 fat jar and JDK 8. Override `BC23_PROBE_REPO` or `BC23_PROBE_JDK` if their existing paths differ. It refuses another host, makes no downloads or network calls, and has a 170-second process timeout plus a five-second kill grace (under 180 seconds total). Outputs stay in a fresh `run-*` directory beside the script; no repository file is modified.

This invokes the real jar's `GameWorld.runRound`, `RobotControllerImpl.attack`, cloud sensing, multiplier machinery, damage and beginning-of-own-turn cooldown decrement. Our scripted `NullControlProvider` subclass performs only a fixture hook or observation. Round 1 contains two distant HQs; launcher and hidden enemy carrier are spawned afterward. Each of 13 independent worlds runs only rounds 1–3. It is a native host fixture, not a server-run, scored game or a contestant bot.

Measured outputs: native pre-CD, multiplier and rounded shot cost, post-CD, next-own-start CD/readiness, native target visibility/attack legality, actual hidden-target HP damage, actual hook invocation count, and hook API-call count. The `charged_cost` field reports the native charge an attack would add; an attack occurs only when `fired` is true, and actual cooldown added is always `post_cd - pre_cd`. Clear unbuffed shots leave `0 -> 10 -> 0`; the unbuffed cloud policy rejects despite native attack legality. A separately labelled forced cloud control bypasses the policy intentionally and demonstrates `0 -> 12 -> 2`: next-turn readiness alone is weaker than returning to zero debt. Additional cases cover sum 10/11, 0.85/0.95/1.05/0.55 rounding, a zero arm and a synthetic low-budget rejection.

**Not measured:** instrumented bot bytecode cost, real final-hook budget availability, crowd-tail safety, target selection quality, damage frequency or strength. No `Clock` call is used. `hook_bytecodes` is null and `instruction_metered` false in every record; the supplied budget is a fixture parameter only. Prescribed boundary CD is installed with `InternalRobot.setActionCooldownTurns(pre + 10)` before the next native own-start decrement; this checks policy boundaries, not historical reachability of every supplied state. Dynamic modifiers use the engine's public boost/destabilize/island-anchor operations, never reflected or overwritten multiplier arrays.

The fixture builds map arrays directly with origin zero, no currents, four islands, symmetric clouds/wells and two HQs; it does not claim Server map-validation coverage. There is no sandbox/player thread or websocket sink, no third-party player code, and no replay result invented. An instrumented current-incumbent diagnostic on the VM remains required before any arm trial.
